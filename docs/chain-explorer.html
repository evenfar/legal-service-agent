原则 1 骨架复用：ReAct 全系统只有一份

「一次对话回合的骨架」全部抽到 BaseAgentRuntime（app/agent/base.py）： 单 Agent 与 MultiAgentOrchestrator 只负责各自的中间段 （路由 + 委托子Agent），提取/降级/压缩/会话骨架零复制。 反面对照：同类项目把约 200 行代码复制粘贴两处，改一处漏一处。

原则 2 tracer 是一等公民

Tracer 以依赖注入的方式进入 LLMClient 与 ToolRegistry， 运行时就能看 token 成本与延迟；评估沙箱直接读 tracer（零 monkey-patch、零全局状态）。 事件类型：llm_call / tool_call / route / redflag_shortcut / injection_blocked / fake_citations_removed / nli_check。

原则 3 Settings 可多实例

评估沙箱用 Settings(memory_enabled=False, mock_mode=True) 构造独立配置，不改全局单例 → 无状态泄漏。 mock_mode 显式化：MOCK_MODE=1 或未配 API Key 自动进离线模式， MockLLMClient 与真实客户端同接口、会读对话历史——离线轨迹与真实模式结构一致。

原则 4 原子写 + 损坏降级

会话持久化先写 .tmp 再 os.replace， 崩溃不会留下半截文件；load_session() 对损坏/版本不符返回 None 视为新会话。 LLM 调用同理：只有瞬态错误（429/5xx/超时）指数退避重试， 4xx 参数错误立刻失败，主模型失败按 fallback_models 链式转移。

真实案例：「朋友借钱拖着不还电话也不接」——逐步展示每一步之后 raw_messages / messages 数组的实际内容变化，以及最终 LegalResponse。 数据取自离线 mock 真实运行的会话文件（session_journey.json）。

本轮为什么是这 2 次 LLM 调用

第 1 次 react · 输入 system+user+tools(9件套) → 输出 tool_calls: load_skill(loan-recovery)
第 2 次 react · 输入 追加 assistant(tool_calls)+tool观察 → 输出 final 纯文本，循环结束
（extract 提取在 mock 模式直接查表构造，不计 llm_call； 真实模式为第 3 次，purpose="extract"）

工具九件套：query_case / update_case_note / query_law_article / search_precedents / calc_limitation / query_court / search_knowledge / recall_user_memory / load_skill （app/agent/tools/registry.py build_tool_registry）。 registry.execute 前做必填参数与类型校验，工具抛异常打包成 {"error": ...} 观察，单工具故障不炸整轮会话。

Phase 2 自适应检索栈（app/agent/rag/adaptive.py · AdaptiveRetriever）。 决策树自上而下：策略路由 → 改写 → 粗召回 → 精排 → Self-RAG 门控 → 三档置信。

query
用户原话，例如「第1062条说的是什么」/「我跟他说要还钱他一直拖着」
▼
route() 启发式策略路由（零成本，不走LLM）
条号正则 _ARTICLE_RE → direct ｜ 原理词 _STEPBACK_RE → stepback
多子问 _MULTI_RE 且长度≥10 → fusion ｜ 零法律术语命中（_LEGAL_TERMS）→ hyde ｜ 其余 → direct
▼
direct 直查
命中: 第X条 / 含法律术语
条号类问题原文最准，不做改写直接召回。
典型: 「民法典第188条」
hyde 假设文档
命中: 口语零术语
先假设一篇"理想答案文档"再去检索，对齐文档语体。
离线: offline_hyde() 查表模板；真实模式走 LLM purpose="hyde"
fusion 多子问拆解
命中: 和/还有/以及 + len≥10
拆成 2~3 个子方面分别召回再融合。
离线: offline_fusion()；真实模式 purpose="fusion_expand"
stepback 退一步
命中: 为什么/什么原理/怎么理解
先退到一般规定层面（如「诉讼时效制度的一般规定」）再检索。
离线: offline_stepback()
▼
粗召回 top-20（RECALL_K=20）
dense 余弦 + BM25 词法 双路 → rrf_merge() RRF 融合（RRF_K=60）
门控 DENSE_GATE=0.55：dense top1 分数 ≥ 0.55 → 语义置信高，关闭 BM25 并票，防词法路稀释排名
▼
Rerank 精排 top-3
规则版 rerank_score()：条号精确命中 +100 > 正文 bigram 重叠（封顶 ×2.0 防长文偏置）> 向量分
引用图谱邻居提名：图邻居须超末位 + GRAPH_BONUS_MARGIN=5.0 分才可顶替第 3 位 —— 图只给机会，精排终裁
▼
Self-RAG 相关性门
relevance() = query 词在 top1 正文的覆盖率，门槛 GATE_THRESHOLD=0.12
不达标 → 换 fallback 策略（direct↔hyde / fusion·stepback→direct）重试一次；仍不达标 → 显式承认失败，不硬答
策略预算 ≤ 2（MAX_STRATEGIES） 检索预算 ≤ 6（MAX_SEARCHES） LLM预算 ≤ 4（MAX_LLM_CALLS）
▼
confident（confidence ≥ 0.5）正常返回 top-3 片段与来源，工具结果直接可用。
low（0.25 ≤ confidence < 0.5）仍返回，但附注「检索依据不够充分，以下片段仅供参考，请谨慎采用」。
refuse（confidence < 0.25 或 relevant=False）清空 chunks，返回「未找到充分依据，建议转人工律师或换种问法」—— 检索层承认失败比幻觉安全。
置信度校准 calibrate()：confidence = relevance(top1) × (0.5 + 排序优势margin)，
margin = clamp((s1 − s2) / max(|s1|,1), 0, 1) —— top1 领先 top2 越多越可信

实测对比（12 条 groundtruth 命中率）

检索栈叠加离线 hash 向量真实 embedding
baseline 单路直查0.330.92
+ Rerank 精排0.581.00
+ 混合检索（dense+BM25 RRF）0.831.00
+ 自适应策略（路由/改写/Self-RAG）0.831.00

解读：离线 hash 向量噪声大，混合检索把 0.33 拉到 0.83（BM25 补词法精度）； 真实 embedding 语义已够强，自适应栈的价值是守住下限（拒答/降级）而非刷上限。

工程要点

组合不改写 AdaptiveRetriever 包住 KnowledgeRetriever， 不碰 .search() 契约 —— search_knowledge 工具零感知
离线确定性 client=None 时四个改写全走查表/模板， 测试可精确断言；传入 client 才走 LLM purpose
预算硬约束 自适应 ≠ 烧钱放大器：策略/检索/LLM 三道上限
RRF 免调权 score(d)=Σ 1/(k+rank)，纯代码融合多路排名
拒答三档 检索层显式承认失败（refuse）， 把"知识库没有"如实传达给上层，而不是硬编
