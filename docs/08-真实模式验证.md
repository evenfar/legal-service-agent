# 08 真实模式端到端验证

> 验证时间：2026-10-08（自动化周期内实测）。此前 README 标注的"未验证路径：真实模型全链路"就此关闭。
> 费用说明：单条消息经 OpenRouter（gpt-6-luna），共 5 次 LLM 调用、5973 tokens，费用极小额。

## 验证方法

`ALLOW_REAL_MODE=1` 起服务（服务端解锁真实模式），`mode=real` POST 一条消息，记录完整事件轨迹与结构化输出。验证后恢复 mock 默认。

## 输入与结果

**输入**：`查一下案件 LS-2026-001 的进展`

**回复**（真实 LLM 生成，markdown 格式化）：

> 案件 **LS-2026-001**（民间借贷纠纷）目前已在**杭州市西湖区人民法院立案**。
> - **下一步：** 举证期限于 **2026年10月12日** 届满
> - **开庭时间：** **2026年11月3日 09:30**
> - **案件金额：** 80,000 元 …

**结构化输出**：intent=case_query | urgency=routine | requires_human=False | confidence=0.99

## 事件轨迹（与 mock 模式结构对照）

| # | 事件 | tokens | 说明 |
|---|---|---|---|
| 1 | llm_call(react) | 1212 | 第一次模型决策 |
| 2 | tool_call: **recall_user_memory** | 0 | **真实模型先查了用户档案**（mock 脚本不模拟此步） |
| 3 | llm_call(react) | 1298 | 第二次决策 |
| 4 | tool_call: query_case | 0 | 查案件 |
| 5 | llm_call(react) | 1610 | 综合产出 final |
| 6 | llm_call(extract) | 897 | 结构化提取 |
| 7 | llm_call(memory_stm) | 956 | 短期记忆巩固 |
| | **合计** | **5973** | 端到端 **13 秒** |

## 三个教学观察

1. **真实模型比 mock 更"守规矩"**：system prompt 里"涉案件建议前先核对用户档案"的指令，真实模型第一步就执行了 `recall_user_memory`——这是 mock 脚本没有模拟的行为差异，说明提示词约束对真实模型有效，也说明 mock 轨迹与真实轨迹"结构一致、顺序可有差异"。
2. **每轮真实成本结构**：ReAct 3 次 + 提取 1 次 + 记忆 1 次 = 5 次调用；其中 react 调用的 prompt_tokens 随历史增长（1212→1298→1610），印证了历史压缩机制的必要性。
3. **13 秒端到端**：瓶颈全在 LLM 网络往返（5 次串行调用），编排层开销可忽略——与 docs/07 性能基准（mock 模式毫秒级）的结论互相印证。
