# 07 · 性能基准

> 实测时间：2026-10-08。对象是 `POST /chat` 的 **mock 模式**（零 LLM 成本），
> 回答"这套编排层到底有多重、单实例能扛多少并发"的量级问题。
> 工具：`app/scripts/bench_api.py`（纯 stdlib，http.client + threading）。

## 口径（读数字前必看）

- **mock 模式**：LLM 全走 Mock 脚本，无任何网络出站——数字反映的是
  编排层自身（红旗检查→ReAct→安全→提取→记忆→持久化）的纯开销；
- **每请求独立 session_id**：服务端对同 session_id 的并发请求用锁串行化
  （**同 session 串行是设计行为**，保护会话历史一致性），复用同一 id 压测
  测到的是锁排队。独立 id 意味着每请求冷装配一个 agent，等于"全是新会话
  首问"的最重口径；
- **每请求新建 TCP 连接**（无 keep-alive），固定问题
  `2023年6月借的钱时效还剩多久`（命中时效工具 + RAG 的典型路径）。

## 环境（wmic 实查）

| 项 | 值 |
|---|---|
| CPU | 12th Gen Intel Core i7-12700KF（12核/20线程） |
| 内存 | 32GB |
| OS | Windows 10 19045（客户端与服务端同机，127.0.0.1 回环） |
| 服务 | Python 3.11.16 · uvicorn 单 worker 默认配置 · `app/api:app` |

## 实测结果（2026-10-08，fresh 服务，预热 5 请求/档）

| 并发 | 请求数 | P50/ms | P90/ms | P95/ms | P99/ms | 均值/ms | QPS | 错误 |
|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| 1 | 50 | 5.3 | 5.6 | 5.7 | 5.9 | 5.4 | 185.4 | 0 |
| 4 | 200 | 13.7 | 16.1 | 21.9 | 26.6 | 14.3 | 275.6 | 0 |
| 16 | 800 | 56.1 | 70.2 | 75.7 | 89.5 | 59.0 | 269.7 | 0 |

## 三条解读

1. **mock 数字 = 编排层开销**。单请求全链路（含新会话冷装配 agent、工具
   执行、会话持久化）约 5ms——规则短路、安全后处理、结构化提取这些
   自研机制层叠起来，相对任何真实 LLM 调用都可忽略。附带观察：复用已
   装配会话时 P95 降至约 49ms（16 并发），即冷装配约占首问延迟的 1/3。
2. **真实模式的瓶颈不在这层，在 LLM 网络 IO**。真实模式一次消息 ≈ 3~5 次
   LLM 调用、秒级延迟（见 [08-真实模式验证](08-真实模式验证.md)），编排层
   5ms 占比不到 1%。本表 QPS **不可外推**到真实模式：真实吞吐上限
   ≈ 并发数 ÷ 单次 LLM 延迟，与表里的 270 无关。
3. **单 worker 的边界清晰可见**。QPS 在并发 4 就到 ~275，加到 16 不升反微降；
   Little's law 验证：269.7 QPS × 59.0ms ≈ 15.9 ≈ 16，说明 16 并发下请求
   已在排队，延迟均值放大 11 倍（5.4→59ms）。瓶颈是 uvicorn 单进程 + GIL +
   同步 endpoint 线程池；要突破需多 worker / 多副本。另外会话 dict 常驻
   不淘汰：~1065 个会话后进程 RSS 50→83MB，演示规模无碍，生产需上限/LRU。

## 复现

```bash
# 终端1：起服务
uvicorn app.api:app --port 8310
# 终端2：压测（stdlib 零依赖）
python -m app.scripts.bench_api --url http://127.0.0.1:8310 \
    --concurrency 1,4,16 --rounds 50 --warmup 5
```

session_id 带运行时间戳标签：对同一服务重复压测也始终是新会话口径，
不会退化成"老会话续聊"。

## 诚实边界

这不是专业压测（没有 wrk/vegeta 级的负载发生器），目的只是**量级感知**：

- 客户端与服务端同机互抢 CPU，stdlib 线程客户端自身也有开销，
  高并发档的 QPS 可能被低估；
- 首轮（冷服务/冷文件缓存）与充分热身后可差 30~50%，表中为
  fresh 服务单轮实测，同口径复测波动约 ±10%（c=16 P95 73.5↔75.7ms）；
- 每档样本 50~800，P99 只有量级意义；
- 结论取稳的部分：单请求 ~5ms、单 worker ~270 QPS 饱和、并发不扩容
  只会线性恶化延迟——这三个量级是可信的。
