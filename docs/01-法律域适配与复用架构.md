# 第01篇 · 法律域适配与复用架构：从「小医」到「小律」

> 一句话目标：机制层（LLM重试/ReAct/记忆/技能/评估/安全框架）从 med-service-agent 原样复用，数据层全部法律域重写——本文用逐文件对照讲清"复用与重写的边界"，并提炼出可迁移到任何新领域的六步方法论。

## 本期目标

- 建立"机制层 vs 数据层"的分层意识：哪些代码与领域无关（永远复用），哪些必须重写（永远域定制）。
- 逐文件看懂 med → legal 的三类改动：原样拷贝 / 域适配（几行之差）/ 全新重写。
- 掌握领域迁移六步清单：schema 枚举 → 工具集 → 子 Agent 拓扑 → 红线规则 → 技能 → Mock 脚本。
- 理解三个法律域特有设计：法条双通道、确定性时效计算器、红线三级优先。

## 背景与数据流

```
【一次 chat() 的流水线：骨架复用，血肉重写】 app/agent/base.py BaseAgentRuntime
  用户输入 ──► handle_redflag() ──命中──► emergency_reply() 直接返回（零 LLM）
                │ 未命中                         app/agent/safety/redflag.py  ← 全新重写
                ▼
        ┌─ 单Agent: LegalAgent.react(SYSTEM_PROMPT, 全量 registry)
        │   app/agent/chat.py + app/prompts/consultant.py          ← 适配+重写
        └─ Multi: MultiAgentOrchestrator → Router.route()
            app/multi_agent/{orchestrator,router,agents}.py        ← 适配+重写
                ▼ 子 Agent 只拿白名单视图 registry.subset(spec.tools)
        ReAct 循环（全系统唯一实现，复用自 med）
                ▼ 工具层: build_tool_registry() 注册法律九件套      ← 重写
        safety_post_process(): scan_output/validate_citations      ← 框架复用
                ▼
        extract_structured() → LegalResponse（schemas/response.py）← 重写
                ▼ finish_turn(): 记忆更新/历史压缩/持久化          ← 复用
```

判定标准只有一条：**这段代码换一个领域还需要改吗？** ReAct 循环、重试退避、
会话压缩换到教育/电商场景一行不用改（复用）；意图枚举、工具、红线词表换领域即失效（重写）。

## 领域迁移六步法（可复用到任何新领域）

1. **schema 枚举**：先写 `IntentType/UrgencyLevel/Response`——意图枚举就是产品需求文档，`requires_human` 定义转人工边界。验收：`TestSchema`。
2. **工具集**：`build_tool_registry()` + `mock_data.py`，区分"读工具"（可出进程/MCP）与"写工具"（update_case_note 只留本地并要求复述确认）。验收：`TestTools::test_build_registry_nine_tools`。
3. **子 Agent 拓扑**：`SUBAGENT_SPECS` 用 frozenset 工具白名单 + prompt 双层声明权限；紧急通道 tools 为空集（不允许在工具上耗时）。验收：`test_specs_whitelists`。
4. **红线规则**：`RED_FLAG_PATTERNS` 宁可误报不可漏报，规则短路发生在进 LLM 之前。验收：`TestRedFlags`（含 `test_no_false_positive_normal`）。
5. **技能**：把长流程写成 SKILL.md（loan-recovery/divorce/labor-arb），Agent 只做"命中→load_skill→按流程执行"。验收：`TestSkills`。
6. **Mock 脚本**：`MockLLMClient` 的 `_plan`（问题→工具序列）/`_route`/`_legal_fields` 决定离线行为——没有这步，离线评估与演示都不可信。验收：`TestMockScripts` + 18/18 评估。

## 核心实现讲解

### 1. 法条双通道：关键词保精确，语义保泛化（app/agent/tools/law.py）

- `query_law_article` 是结构化直查：先精确匹配 `LAW_ARTICLES`（键为中文条号），再走 `_normalize_article()` 把"第1062条"归一化成"第一千零六十二条"（`_num2cn` 处理 1000~1260 范围），最后按 `LAW_TOPICS` **最长主题词匹配**（"家暴赔偿"优先于"赔偿"）。未命中显式返回 `available_topics` 并引导去 `search_knowledge`。
- `search_knowledge`（复用 med 的壳）走 RAG 语义检索，适合"合同可以口头订立吗"这类泛化问法。
- 设计理由：法条是**精确引用型知识**——条号差一位就是另一条规定，向量相似度会引入"相邻条干扰"；而口语问题又必须靠语义召回。两通道互补，`query_law_article` 命中主题词时还会返回 hint 主动引导二次检索。

### 2. 诉讼时效计算器：确定性工作不交给模型（app/agent/tools/limitation.py）

- `calc_limitation(case_type, start_date)` 用 `LIMITATION_RULES` 查年限（一般民事 3 年/劳动仲裁 1 年/行政复议 60 日），`timedelta` 精确算 `days_left`，按阈值分四档 status（已过时效/临近时效/时效尚可/时效充足），`WARNING_DAYS = 90` 内 `warning=true`。
- 为什么必须是代码：日期算术要**零错误**（差一天可能丧失胜诉权）、**可解释**（返回 `basis` 依据条文）、**瞬时**。CONTRACT_PROMPT 明写"禁止口算'还有X年'"。
- 边界意识：已过时效也不说"没救了"，advice 指出中断/中止事由的救济路径。

### 3. 法律红线三级优先（app/agent/safety/redflag.py）

- `RED_FLAG_PATTERNS` 按优先级组织：①人身安全（家暴/跟踪/威胁/拘禁/抢夺）②证据灭失（要删记录/不认账）③时效临界（"快三年了"）。`emergency_reply(flags)` 按同一顺序取第一个命中的模板：人身安全给 110/人身安全保护令，证据给"固定证据、别打草惊蛇"，时效给"提供日期，我用工具精算"。
- 与 med 的安全对照：

| 维度 | med（医疗） | legal（法律） |
|---|---|---|
| 红线对象 | 急症症状平级列举（胸痛/呼吸困难/心理危机…） | 三类且有优先级：人身 > 证据 > 时效 |
| 应答形态 | 单一 `_EMERGENCY_REPLY_TEMPLATE`（一律拨 120） | `_EMERGENCY_REPLY_TEMPLATES` 分级 + `_EVIDENCE_REPLY` + `_LIMITATION_REPLY` |
| 时效类红线 | 无 | 有（对应"差一天丧失胜诉权"的领域风险） |
| 短路位置/第二防线 | `handle_redflag` 规则短路；structured output 的 urgency 兜底 | 同一短路点；另有 Router 的 emergency 分类与 `_legal_fields` 的 urgency 升级 |
| 意图枚举 | emergency=急症 | emergency=紧急红线（人身/证据/时效三义） |

### 4. Multi-Agent 拓扑（app/multi_agent/）

- `Router.route()`：temperature=0 + max_tokens=10，输出用"受控词表包含匹配 + DEFAULT_AGENT 兜底"——分类要确定性，模型多吐字也不崩。
- `MultiAgentOrchestrator` 继承 `BaseAgentRuntime`，`chat()` 中间段只有"路由 + 委托"：全量 `build_tool_registry` 注册一次，各子 Agent 用 `registry.subset(set(spec.tools))` 拿白名单视图；emergency 子 Agent 白名单为空。

### 5. Mock 脚本即"离线领域知识"（app/llm/client.py::MockLLMClient）

- `_plan(user)` 按问题类型排出工具序列（案号→query_case；"时效/还剩多久"→`_extract_date` 抽日期 + `_limitation_type` 判类型→calc_limitation；"第\d+条"→query_law_article；离婚/欠钱/欠薪→load_skill…）。
- `_final_text` 从 `_tool_results(messages, since_last_user=True)` 取**最近一轮**工具结果拼回复（历史轮的素材不算数），且工具失败必须如实转达 error。
- `_legal_fields` 是结构化提取的规则版：免责话术≠转人工（requires_human 只认"报警/110/保护令/临近时效"等明确行动信号）。

### 6. 复用的代价：残留与防御

`app/agent/base.py::safety_post_process` 里仍保留 `query_lab_report`（med 的检验工具）分支——法律 registry 里没有这个工具名，`used` 列表永远不包含它，所以是无害死代码；但它提示：**按名匹配的安全防线依赖工具名**，复用基类时这类残留要么清理、要么改造（见练习 3）。

## 知识点与面试考点

1. **多领域 Agent 项目怎么组织代码复用？** 要点：机制层（ReAct/重试/记忆/评估框架）与数据层（schema/工具/词表/prompt）物理分层；适配点收敛到"领域参数"（枚举、白名单、词表），base.py 只留钩子 `_init_components/_restore_extra`。
2. **意图枚举为什么是迁移第一步？** 要点：IntentType 是需求的结构化表达，下游 prompt/工具/评估用例全围绕它展开；枚举错则后面全错（emergency 在法律域是三义复合，医疗域是单一急症）。
3. **精确查询和向量检索什么时候各用其一？** 要点：标识符型查询（条号/案号/单号）走结构化直查零误差；自然语言模糊问法走 RAG；法条双通道 + 最长主题词匹配 + miss 时显式引导，是"关键词保精确、语义保泛化"的完整落地。
4. **哪些工作绝对不该交给 LLM？** 要点：日期/金额等确定性算术（calc_limitation）、红线判定（宁可误报不可漏报且要零延迟）、权限控制（工具白名单）；LLM 负责自然语言理解与流程编排。
5. **规则短路为什么放在路由之前？** 要点：`handle_redflag` 在 `Router.route` 之前执行（test_redflag_before_router 验证）——人身安全等不得一次额外的 LLM 分类往返；LLM 分类只是规则表漏报时的兜底。
6. **子 Agent 权限最小化怎么落地？** 要点：frozenset 白名单生成 registry 视图 + prompt 再声明一遍（双层约束）；紧急通道工具集为空，防止紧急场景消耗在工具调用上。
7. **Mock 客户端凭什么可信？** 要点：与真实客户端同接口、读取真实对话历史（含工具结果）、步数计数按轮次重置（`_bump` 键含 turn_no）——离线轨迹与真实模式结构一致，测试/评估/演示才有意义。
8. **复用基类的隐患？** 要点：按工具名匹配的安全逻辑（query_lab_report 残留）会随领域工具集变化而静默失效或变死代码；复用时要审出所有"名字耦合点"。

## 动手练习

1. **换域演练**：参照六步法把本项目迁移到"教育留学咨询"域——写出新的 IntentType/UrgencyLevel、5 个工具签名、3 个子 Agent 白名单、3 组红线词表。只允许改 C 类文件，跑 `pytest` 全绿。
2. **双通道极限测试**：构造 5 个 query_law_article 应该失败但 search_knowledge 应该命中的问题（如"网上购物能随时退货吗"），观察 miss 返回的引导话术，再对比只走 RAG 的召回质量，写一段双通道取舍分析。
3. **清理复用残留**：把 `base.py::safety_post_process` 中的 `query_lab_report` 分支改造成法律域等价物——当 `calc_limitation` 返回 `warning=true` 时给回复加显著警示并置 `forced_human=True`；注意按字段取值（`json.loads(out).get(...)`）而非子串匹配，并补一条测试。
